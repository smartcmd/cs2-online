# CS2 网页版 · 联机

浏览器里的 5v5 爆破模式。玩家自选阵营，空位由机器人补上，同一个房间名进同一局。

## 本地运行

```sh
npm install
npm start          # 打开 http://localhost:8080
```

地图使用 Dust II 导出文件的完整网格，保留全部三角面和坐标精度。表面使用原版贴图的分级 WebP 版本和源 UV，透明轮廓保留源分辨率。颜色方案约 41.73 MiB，带必要法线、粗糙度细节约 42.31 MiB。大厅的「浏览沙二地图」可查看包点、A 小道、CT 通道、中门和 B 洞。来源及无损重建方法见 [ASSETS.md](ASSETS.md)，竞技性约束见 [AGENTS.md](AGENTS.md)。

同一个 Wi-Fi 下的朋友可以用 `http://你的电脑IP:8080` 进来。

大厅和暂停菜单均有全屏按钮，也可按 `Alt+Enter` 切换。按 `Esc` 释放鼠标后，点击“回到游戏”重新捕获鼠标。

首次在触屏设备打开时使用中画质：100% 渲染分辨率、抗锯齿、1024 像素阴影和颜色版材质。高画质加载法线与粗糙度细节；已保存的细节选项继续生效。渲染帧率默认上限 60，可选 30、60、90、120 或不限；输入预测与指令发送继续按浏览器回调频率运行。画质菜单还可独立设置纹理过滤、表面凹凸、阴影精度和枪模位置。已保存的画质设置继续生效。静态地图阴影缓存后与人物实时阴影合成；视野裁剪按材质区域计算球形包围体，并在颜色绘制前检查包围盒，使用完整源网格。人物共享材质与动画轨道，只在首次使用某个动作时建立绑定；人物和枪械的材质程序在载入阶段预编译。

角色和主要武器使用带动画的 CS2 模型，配合录制音效。第一人称切出动画按资源原始时长播放，武器就绪时间由现有游戏规则决定；枪模默认放在右下方，可切换为紧凑或居中布局，世界视野和准星不变。贴图缩至 512 像素，模型与音效经 HTTP 压缩后的首次传输约 10.95 MiB。细节地图、这组资源和共用脚本合计约 53.58 MiB。带内容校验值的资源 URL 使用一年不可变缓存，刷新仍需解码及建立 GPU 数据。资源来源与 FAMAS 等简化项见 [ASSETS.md](ASSETS.md)。

## 自动测试

运行 `npm test`。测试使用 Node.js 内置测试工具，覆盖炸弹与胜负结算、购买和武器规则、输入校验、客户端菜单与重连，以及真实 WebSocket 的房间人数、聊天隔离和断线清理。三个机器人难度各运行 10 分钟游戏时间，检查状态、结算和自动开新局。

联机测试会自动启动独立服务并分配空闲端口，结束后关闭，不占用本地 8080 端口。

用 `/?perf` 打开本地页面可测量十二处地图视角或当前对局的 CPU/GPU 耗时、绘制调用和三角面数量，并对比缓存与完整重绘的画面。当前画面采样记录 600 帧，并分别统计输入预测、网络状态校正、人物动画、第一人称枪模和绘制耗时，保留最慢的几帧用于定位尖峰。GPU 计时需要浏览器提供计时扩展。`npm run test:shadows` 提供独立的阴影像素回归页面，检查物体移动、静态深度缓存和分辨率切换。`npm run test:materials` 检查源贴图数组与标准材质的 GPU 像素差异，`npm run map:size` 统计完整下载量。中低画质的“省显存”将颜色纹理存为 RGB565，独立透明遮罩保持原精度。颜色版纹理及 mipmap 的格式预算约 155 MiB，带法线细节约 183 MiB；高、极高画质默认“完整”颜色精度，分别约 310 / 337 MiB。驱动实际占用可能不同，完整网格和其他资源另计。手机浏览器的实际内存、帧率与温升仍需在目标设备上测量。

机器人回归测试还覆盖 60 组真实地图路线、不可达目标、台阶恢复、队伍站位、拆弹接替和跨楼层交互。运行 `npm run bots:audit` 可另外检查三个难度、四个固定随机种子下累计 60 分钟的模拟，记录持续转圈、停滞和每帧耗时，报告写入 `.cache/bot-review/match-audit.json`。可用 `BOT_DIFF=normal BOT_SEED=29 npm run bots:audit` 单独复测一组；这些检测覆盖固定场景，不保证所有对局都不会卡住。

## 部署到云服务器

服务器把房间存在内存里，**只能跑一个实例**，也不能开自动休眠，否则房间会丢失或者玩家会被分到不同机器上。下面三种方式任选一种。

### 方式一：自己的 VPS（国内玩家推荐）

适合阿里云、腾讯云这类云服务器。玩家主要在国内的话，延迟最低。

```sh
docker build -t cs2-web-online .
docker run -d --name cs2 --restart unless-stopped -p 80:8080 cs2-web-online
```

记得在云服务器的安全组里放行 80 端口。要用 HTTPS 的话，前面加一层 Nginx 或 Caddy 反向代理，并转发 WebSocket（路径 `/ws`）。Caddy 的写法：

```
your.domain.com {
  reverse_proxy 127.0.0.1:8080
}
```

用 Caddy 时，把上面 docker run 的端口改成 `-p 127.0.0.1:8080:8080`。

### 方式二：Fly.io

```sh
brew install flyctl
fly auth login
# 先把 fly.toml 里的 app 名改成你自己的，primary_region 选离玩家近的机房
fly launch --copy-config --no-deploy
fly deploy
fly scale count 1
```

### 方式三：Render

把这个目录推到 GitHub，在 Render 控制台选 **New → Blueprint** 并指向该仓库，它会读取 `render.yaml`。免费版闲置 15 分钟会休眠，想长期在线要选付费档。

## 文件结构

| 路径 | 作用 |
| --- | --- |
| `shared/dust2-world.js` | 客户端与服务器共用的三角面碰撞、坡道移动和导航 |
| `shared/dust2-mesh.js` | 紧凑地图解码；同一几何用于显示和碰撞 |
| `public/maps/` | 已生成的小体积沙二模型、雷达与资源清单 |
| `shared/sim.js` | 游戏模拟：地图、物理、武器、机器人 AI、回合与经济。服务器和浏览器共用这一份 |
| `server.js` | HTTP 服务、WebSocket 和房间管理。服务器以每秒 30 次的频率运行游戏模拟，每秒向玩家发 15 次状态 |
| `public/index.html` | 浏览器客户端：渲染、本地移动预测、插值、HUD、大厅和聊天 |

## 联机机制

- **权威在服务器**：命中、伤害、金钱、回合结果都由服务器计算，客户端只负责发送按键和视角。
- **本地预测**：自己的移动在本地立刻生效，收到服务器状态后再校正，所以高延迟下走路也不粘手。
- **延迟补偿**：开枪时，服务器把其他玩家回退到你开枪时屏幕上看到的位置，再判定命中。
- **防作弊**：服务器限制客户端的操作速度，防止加速；射速、弹药、购买资格都在服务器校验。敌人的位置会发送给所有客户端，所以挡不住透视外挂。

## 测试用环境变量

这些变量只用于本地调试，**正式部署时不要设置**。

- `CS2_DEBUG=1`：允许客户端在服务器上执行调试代码。
- `CS2_LAG_MS`、`CS2_JITTER_MS`：模拟网络延迟和抖动。

| 变量 | 默认值 |
| --- | --- |
| `PORT` | `8080` |
| `NODE_ENV=production` | 缓存静态文件，不再每次请求都重新读取 |
