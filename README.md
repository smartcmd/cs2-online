# CS2 Online

在浏览器里玩 Dust II 5v5 爆破对战。使用 Node.js、WebSocket 和 Three.js，支持多人房间、机器人补位、购买武器、安包与拆包，以及桌面和触屏操作。

这是社区制作的网页游戏，与 Valve 无隶属关系。地图和部分角色、武器、音效来自 CS2 资源导出，玩法、物理与渲染由本项目实现。资源来源及复现范围见 [ASSETS.md](ASSETS.md)。

## 开始游戏

需要 Node.js 20.9 或更新版本。

```sh
git clone https://github.com/smartcmd/cs2-online.git
cd cs2-online
npm ci
npm start
```

打开 <http://localhost:8080>，输入昵称和房间名，选择阵营后加入。相同房间名会进入同一局，空位由机器人补上。局域网玩家可访问 `http://服务器局域网IP:8080`。正式外网部署请使用 HTTPS。

仓库已包含运行资源，首次启动无需重新导出地图或下载原始模型。

| 操作 | 桌面按键 |
| --- | --- |
| 移动 / 跳跃 | WASD / 空格 |
| 慢走 / 蹲下 | Shift / Ctrl |
| 开火 / 瞄准 | 鼠标左键 / 右键 |
| 换弹 / 丢枪 | R / G |
| 购买 / 使用或拆包 | B / E |
| 切换武器 | 1、2、3、5 |
| 计分板 / 暂停 | Tab / Esc |
| 全屏 | Alt+Enter，或菜单中的全屏按钮 |

触屏设备提供移动摇杆、滑动视角和动作按钮，建议横屏。桌面按 Esc 释放鼠标后，点击“回到游戏”恢复鼠标捕获。

## 地图、画面与性能

- Dust II 使用源导出的完整网格、源 UV 和分级 WebP 贴图。模型打包保留三角面和坐标精度，竞技性约束见 [AGENTS.md](AGENTS.md)。
- 地图颜色方案约 41.77 MiB，加入法线和粗糙度细节约 42.34 MiB。人物、武器和音效另约 10.95 MiB。细节地图与全部共用资源首次传输约 53.62 MiB，运行 `npm run map:size` 可查看明细。
- 带内容校验值的资源使用一年不可变缓存。刷新可复用下载缓存，但浏览器仍需解码地图并建立 GPU 数据。
- 静态地图阴影缓存后与人物实时阴影合成。视野裁剪使用源网格包围体，天空与反射在载入时预计算。
- 画质菜单可设置渲染分辨率、抗锯齿、阴影、纹理过滤、材质细节、颜色精度、帧率上限和第一人称枪模位置。

触屏设备首次打开默认中画质、60 FPS 上限和颜色版材质。高画质加载额外材质细节。设置会保存在当前浏览器。iPhone 和安卓是优化目标，手机真机上的持续帧率、显存占用和温升尚未完成验证。

大厅中的“浏览沙二地图”可以检查 A/B 点、中门、CT 通道等位置。天空、间接光照及部分材质为网页版近似，Source 2 的完整渲染效果仍有差异。FAMAS 使用通用手臂动作和部分借用音效，详情见 [ASSETS.md](ASSETS.md)。

## 自动测试

运行 `npm test`。测试使用 Node.js 内置测试工具，覆盖炸弹与胜负结算、购买和武器规则、输入校验、客户端菜单与重连，以及真实 WebSocket 的房间人数、聊天隔离和断线清理。三个机器人难度各运行 10 分钟游戏时间，检查状态、结算和自动开新局。

联机测试会自动启动独立服务并分配空闲端口，结束后关闭，不占用本地 8080 端口。

用 `/?perf` 打开本地页面可测量十二处地图视角或当前对局的 CPU/GPU 耗时、绘制调用和三角面数量，并对比缓存与完整重绘的画面。当前画面采样记录 600 帧，并分别统计输入预测、网络状态校正、人物动画、第一人称枪模和绘制耗时，保留最慢的几帧用于定位尖峰。GPU 计时需要浏览器提供计时扩展。测试面板可显示第一人称手部/枪模；隐藏调试界面后按 H 恢复，便于拍摄同视角对照。`npm run test:shadows` 提供独立的阴影像素回归页面，检查物体移动、静态深度缓存和分辨率切换。`npm run test:materials` 检查源贴图数组与标准材质的 GPU 像素差异，`npm run map:size` 统计完整下载量。中低画质的“省显存”将颜色纹理存为 RGB565，独立透明遮罩保持原精度。颜色版纹理及 mipmap 的格式预算约 155 MiB，带法线细节约 183 MiB；高、极高画质默认“完整”颜色精度，分别约 310 / 337 MiB。驱动实际占用可能不同，完整网格和其他资源另计。手机浏览器的实际内存、帧率与温升仍需在目标设备上测量。

机器人回归测试还覆盖 60 组真实地图路线、不可达目标、台阶恢复、队伍站位、拆弹接替和跨楼层交互。运行 `npm run bots:audit` 可另外检查三个难度、四个固定随机种子下累计 60 分钟的模拟，记录持续转圈、停滞和每帧耗时，报告写入 `.cache/bot-review/match-audit.json`。可用 `BOT_DIFF=normal BOT_SEED=29 npm run bots:audit` 单独复测一组；这些检测覆盖固定场景，不保证所有对局都不会卡住。

## 部署

房间状态保存在单个 Node.js 进程的内存中。请运行一个服务实例并关闭平台自动休眠；重启会结束当前对局。多实例需要额外实现房间路由。

```sh
docker build -t cs2-online .
docker run -d --name cs2-online --restart unless-stopped \
  --log-opt max-size=10m --log-opt max-file=3 \
  -p 127.0.0.1:18080:8080 cs2-online
```

在 DNS 中把域名的 A 记录指向服务器公网 IPv4，并放行 TCP 80、443。使用 Caddy 反向代理，自动签发 HTTPS 证书并转发 WebSocket：

```caddyfile
cs2.example.com {
    reverse_proxy 127.0.0.1:18080
}
```

把示例域名换成自己的域名。服务的 `/healthz` 返回 `ok`，`/rooms` 提供房间列表，WebSocket 路径为 `/ws`。代理应保留资源服务返回的缓存和 `Content-Encoding` 响应头。`Dockerfile` 使用非 root 用户运行并配置健康检查。

| 环境变量 | 用途 |
| --- | --- |
| `PORT` | HTTP 监听端口，默认 `8080` |
| `NODE_ENV=production` | 在进程内缓存静态文件，Docker 镜像已设置 |

调试变量 `CS2_DEBUG=1` 允许客户端在服务器进程执行调试代码，正式部署必须保持关闭。`CS2_LAG_MS` 和 `CS2_JITTER_MS` 用于本地模拟网络延迟，正式部署也应保持未设置。

## 代码结构

| 路径 | 作用 |
| --- | --- |
| `server.js` | HTTP、WebSocket、房间管理和服务器权威模拟 |
| `shared/sim.js` | 共享游戏规则：武器、经济、回合、炸弹与机器人 |
| `shared/dust2-world.js` | 三角面碰撞、坡道移动与导航 |
| `shared/dust2-mesh.js` | 无损地图解码 |
| `public/index.html` | 大厅、HUD、输入预测与渲染循环 |
| `public/maps/`、`public/game/` | 已构建地图、人物、武器、动画和音效 |
| `scripts/` | 离线资源构建、体积统计与 GPU 检查工具 |
| `test/` | Node.js 回归测试和浏览器 GPU 测试页面 |

服务器每秒运行 30 次模拟，向玩家每秒发送 15 次状态。客户端使用本地移动预测和远端插值；服务器校验命中、伤害、购买和武器规则，并在命中判定中做延迟补偿。敌人的位置仍会发送到客户端，当前实现不能防止透视外挂。
